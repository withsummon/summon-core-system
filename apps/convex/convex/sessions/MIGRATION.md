# Native authenticated session management

## Revocation boundary

**Revocation blocks refresh-token renewal. An already issued access JWT can remain usable by ordinary application endpoints until it expires. This is not immediate global sign-out.** Installed Convex Auth0.0.95 defaults JWT duration to one hour (`implementation/tokens.ts`); current auth.ts does not override it. Session-management endpoints themselves load and validate the live session, so a revoked session cannot list/revoke sessions again. MCP sensitive credential operations already enforce live sessions independently.

Official documentation consulted through Context7 `/get-convex/convex-auth`: [session validity](https://github.com/get-convex/convex-auth/blob/main/docs/pages/advanced.mdx), [session authorization](https://github.com/get-convex/convex-auth/blob/main/docs/pages/authz.mdx). Installed source was checked against docs: `authSessions`, indexed refresh token chains, `getAuthSessionId`, private `deleteSession`, and exported action-only `invalidateSessions`.

`invalidateSessions` revokes all actor sessions except an exclusion list. It cannot safely implement a single-session target from a preloaded exclusion list because a concurrent new session would be unintentionally revoked. Its exact-session helper is private. Native `sessions.index.revoke` therefore uses the same canonical tables/index and deletes the chosen owned session plus every associated refresh token in one mutation. No alternate credential/session store, private package import, token parsing, or copied cryptography is introduced. A1001-row bounded read rejects chains over1000 before changing anything, rather than partially revoking. This explicit capacity limit remains a follow-on for bounded asynchronous cleanup if real session rotation exceeds it.

`sessions.index.list({paginationOpts})` returns safe metadata only: id, createdAt, expiresAt, isCurrent; cursor/isDone and the revocation notice. It lists only the current actor's records, includes expired rows with explicit expiresAt, and accepts the shared1..50 page budget. It does not claim device/IP/browser/last-active information that Convex Auth does not capture. `revoke({sessionId})` rejects absent or unowned sessions identically and returns revokedCurrent, which clients should use to clear their own local auth with the existing signOut owner. A live actor session is required for both operations; a bare user subject is insufficient.

Inherited `app/views/user/base.py:UserSessionEndpoint` is an authenticated-state/current-user probe, not a session inventory API. The searched inherited app routes do not expose list/revoke-other-device operations. Device/DeviceSession models exist separately. This native control is an account-security capability and does not imply a migrated legacy device-metadata contract. Existing auth probe/signIn/signOut remain unchanged.

## Required global closure, separately coordinated

Canonical `identity/access.requireUser` presently calls getAuthUserId and loads only users. It is the sole application getAuthUserId call. Immediate domain revocation belongs there, by verifying current authSessions actor/expiration, alongside a client boundary that handles a valid JWT with a missing session. Forty-nine source/test-support files currently construct withIdentity subjects, many as bare user IDs; tests must migrate to genuine synthetic authSessions rather than a production bypass. Asset and assistant HTTP entrypoints also initially inspect getUserIdentity; their subsequent domain authorization must be sampled during closure. Do not add an ephemeral fallback accepting sessionless production identities. This slice does not make the broad change.

## Verification and rollout

Four module BDD cases pass: safe paginated owner list and foreign-target denial; all refresh descendants removed while current session survives; expired/mismatched/current-revoked denial; over-limit chain failure with all rows retained. Native TS7, scoped Oxc and diff checks pass. No schema changes, dependencies, deployment, real-user revocations, frontend controls or browser acceptance are claimed. Primary owns runtime activation and later immediate-session enforcement.
