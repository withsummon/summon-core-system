# Documents and resources: bounded backend slice

## Current owner and public boundary

`documents/schema.ts` owns metadata and immutable snapshot fields; generated Convex API types derive from the functions. `documents/access.ts` owns document visibility. `resources/schema.ts` owns external links. Mutations authorize current workspace/project memberships on every call.

The legacy `Page` model holds Yjs binary, editor JSON, rendered HTML, view/logo properties, owner and multi-project visibility. `summon/services/page_document.py` writes generated metadata under `view_props.summon_document`; that object includes markdown, source transcript, summary, decisions, citations and other generator-owned fields. This slice retains the complete object in `viewProps` without translating or deleting its keys. External source/ID, category, tags, client and opportunity references are also retained. Native IDs and camelCase fields are a new API, not a compatibility replacement for the Django serializers.

## Implemented behavior

- Document create/read/update, owner-controlled visibility and lifecycle, workspace-scoped paginated listing, and private/public/global/multiple-project access. Workspace guests cannot write; project guests cannot write project-visible documents. Metadata link updates require write access to every referenced project. Limits: 20 project links and 100 tags.
- Authenticated append-only binary snapshot revisions, atomic compare-and-swap on the current revision, historical/current reads. A stale save fails and never replaces the committed bytes. Binary limit is 512 KiB; HTML and JSON are each limited to 100,000 characters. There is no HTML-only save path and no deletion of historical revisions.
- Resource external HTTP/HTTPS links with project/document/client relationships, creation/update actor IDs, title/category/description, update ordering, pagination and soft deletion. Existing and new relationships are checked when updating.
- Paginated lists may return an empty page with a continuation cursor when the scanned records are inaccessible. Consumers must use `isDone`/cursor, not page length, to determine exhaustion.

## Existing collaboration owner remains active

`apps/live/src/lib/auth.ts` checks the Django cookie/current-user endpoint. `apps/live/src/extensions/database.ts` loads binary through `getPageService`, passes it to Hocuspocus, and stores the merged Yjs state plus HTML/JSON generated by `@plane/editor`. That service still targets Django. This slice does not rewire it.

The snapshot transport treats binary as opaque bytes. It neither validates Yjs encoding nor proves that the supplied HTML/JSON correspond to the bytes. The dedicated `apps/live/src/convex` room server now implements authenticated Yjs load/merge/save and editor-derived renderings with bounded conflict retries. Its actual local network smoke verifies two-user editing, persistence, lock and revocation. The existing product editor remains on the legacy service; see the live module README for remaining token refresh, title synchronization and client integration work. The backend tests alone prove transport byte preservation and conflict rejection, not concurrent rich-text editing.

## Legacy behavior still requiring migration

Page parent/subpage hierarchy, labels, move aliases, sort/reorder operations, ownership transfer, deleted-page restore, timed version generation/restore, PageLog backlink/file extraction, live force-close/title-sync hooks, full-text stripped HTML, and API serializer projections remain outside this slice. Lifecycle authorization is currently owner-only; legacy project-admin lifecycle exceptions need their own parity pass.

Resource credential relationships require the credential domain owner. File uploads remain FileAsset-owned. Generated artifacts, download/PDF/DOCX rendering, template aliases, meeting summary/source-transcript projections, assistant automation, and context record CRUD are not migrated merely because their metadata can be stored here. No Django or Hocuspocus retirement is authorized by these backend checks alone.
