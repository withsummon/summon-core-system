# Native recent visits and sidebar preferences

Production inheritance: `plane/db/models/recent_visit.py`, `bgtasks/recent_visited_task.py`, `app/views/workspace/recent_visit.py`, `db/models/workspace.py` and `app/views/workspace/user_preference.py`. Guest workspace access is retained. These are personal records; no API accepts another actor's ID.

`navigation.recent.record` accepts typed issue/page/project targets after current workspace and target authorization. The existing target projection owner reuses canonical project membership, task guest visibility and document access. `list` rechecks those permissions and emits no revoked target metadata. It returns at most20 retained rows, optionally filtered by type. Native issue/page map to tasks/documents, not legacy UUIDs. React subscriptions must not record visits implicitly: the frontend navigation producer should call the explicit mutation once after navigation succeeds.

Inherited ordering is deliberately exact: rows are ordered by first creation descending, revisits update visitedAt without moving the row, and insertion evicts the oldest-created row at20. This differs from an LRU list. Legacy model declares more entity types and background producers record cycle/module/view too, but its public list explicitly exposes only issue/page/project. Native only stores the three exposed types; unsupported hidden producers do not consume its retention budget. No names are cached. Current authorization filtering may return fewer than20 items, with no inaccessible placeholders. The mutation serializes retention and deduplication transactionally.

`navigation.preferences.ensure` explicitly initializes missing rows, replacing legacy writes from GET. Seven keys retain enum order: views, active_cycles, analytics, drafts, your_work, archives, stickies. Initial sortOrder is65535 +10000\*index; drafts/your_work/stickies are pinned. Repeat ensure never overwrites user values. `list` returns initialized plus ascending ordered persisted preferences, without ephemeral defaults. `update` accepts up to seven distinct keys and optional isPinned/sortOrder fields, with captured per-row expectedRevision. One stale row rejects the complete batch. Finite bounded numeric order preserves inherited fractional ordering. Guests may manage their own preferences. Unknown keys are rejected by the canonical validator instead of silently ignored.

New navigation tables are additive, initially empty; there is no existing native state to backfill and no automatic import of legacy user visits/preferences. Legacy routes and UI remain available until the frontend calls these owners. No deployments, live navigation acceptance or legacy retirement claimed. Parent owns deployment/browser gates.

Module BDD covers20-row retention/revisit order, type filtering, actor privacy, guest access and revoked membership, project archival, task guest restriction and document privacy, exact preference defaults/idempotence, and atomic stale-batch rollback. Five focused tests, native TS7 and scoped lint pass at implementation checkpoint.
