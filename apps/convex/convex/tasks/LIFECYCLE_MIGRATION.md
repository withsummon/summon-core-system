# Task archive and recovery

Deployed to the local Convex backend at 08:48:46 on 2026-09-27. Backfill updated 1,503 tasks over 31 bounded pages; a second 31-page scan changed zero. Remote deployment remains pending.

Legacy archive/unarchive permits project writers, archive only completed/cancelled. Legacy delete permits creator or project admin and schedules cascading soft deletion. Legacy `restoreIssue` is unarchive; `restore_related_objects` is unimplemented. Native reversible trash deliberately retains all related records without cascading or purging. Delete/restore require current project access and creator or project admin; a guest creator is allowed. Archive/unarchive require current workspace/project writer access. Archived tasks and comments remain readable but cannot be edited. Restoring a previously archived task returns it to archive.

`tasks/access.ts` owns lifecycle visibility. Existing project/workspace owners still authorize each public caller. The former notification recipient predicate is moved here as taskCanRead and reused by notification delivery/retrieval and assistant action pagination; no catch-all authorization failure filtering is introduced. requireConversation only enforces workspace/owner access, so task-row filtering preserves accessible action rows in mixed-project conversations. Ordinary task lists/reports exclude inactive tasks; archived detail readers retain current project authorization. Deleted detail is restricted to recovery authorization. Descriptions and comments cannot be fetched through their independent endpoints for deleted tasks. Subscriptions, notifications, cycle/module/meeting links and graph edges are retained. Notification projection suppresses deleted task content, including existing events; restore may make retained notification history visible again. Pending assistant actions cannot confirm against inactive tasks or a stale task revision.

Authorized writers can unlink retained hidden relation/meeting links through title-free placeholders. Open cycles and editable modules also expose inactive task placeholders with only task ID and revision, so writers can detach retained links without creator-only trash-content access. Completed/archived cycles and archived modules retain their existing edit restrictions. Parent response is `{task,hasParent}`; hidden parent yields null task while retaining detach affordance. This is content protection, not identifier secrecy: existing relation records and link identities can expose referenced IDs. Cleanup of an existing graph/cycle/module relation is an explicit exception to inactive content immutability: it updates that endpoint’s task revision/event without changing title/status/body or making it publicly readable. This keeps stale restore/edit attempts detectable and does not recreate a removed relationship. Existing graph edges continue participating in cycle checks until explicitly removed.

Optional archivedAt/deletedAt are exclusively an existing-row migration contract. New task creation initializes both null. Internal backfill reads at most50 tasks /1MB per invocation, patches only missing fields and preserves lifecycle state/revisions. After all known deployments have a complete scan and zero-change verification, make both fields required and switch active/project/workspace query plans to indexed lifecycle equality. During transition all scans are bounded pages, filtered pages retain continuation cursors. Overview examines at most100 candidates and returns at most20 active tasks with explicit candidate coverage; it does not promise globally latest20 when older pages remain.

Out of scope: permanent purge, legacy asynchronous cascade parity, bulk deletion/archive, configurable guest project policies, REST/PAT compatibility and legacy detailed activity payloads. Lifecycle reuses canonical taskChanged and existing generic updated events; no parallel event writer.
