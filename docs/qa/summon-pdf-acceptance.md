## Evidence rules

- `LOCAL_PASS` means the local candidate passed the named automated/static/build gate. It never substitutes for authenticated browser/read-back acceptance.
- `STATIC_ROUTE_PASS` means only that the required route file exists and the deterministic route guard passed. It is not browser or business acceptance.
- `BLOCKED_LOCAL_RUNTIME` means the browser flow was not executed because no local web/API application was reachable. On 2026-08-22, ports 3000, 3001, and 8000 returned HTTP `000`; `docker compose ps` listed only test PostgreSQL, MinIO, RabbitMQ, and Redis services.
- `PASS_BROWSER_LOCAL` requires the listed interaction and read-back, unique desktop and mobile evidence, the row-specific accessibility checks, and zero unexpected console errors.
- `PASS_LIVE` is separate from local proof and requires the same flow against an explicitly authorized deployed revision.
- `LIVE_BASELINE` records observed deployed behavior only. It does not prove the uncommitted local candidate.
- `LIVE_NOT_DEPLOYED` means the deployed app demonstrably lacks a route or state that exists in the local candidate.
- A route load, static source inspection, type check, build, or screenshot without the required interaction never upgrades a row to browser PASS.
- No credential value, API key, session, copied PDF business record, or fake screenshot may appear in evidence.
