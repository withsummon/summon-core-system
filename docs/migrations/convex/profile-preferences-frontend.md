# Native account preferences

Account details retains the existing name/timezone form and adds a separate preference editor. Both capture the canonical shared profile revision when opened. A preference save does not replace the name draft; concurrent saves conflict without overwriting either captured draft. Preference edits spread the full generated object, retaining onboarding, language, week-start, rail, cursor and last-workspace fields not owned by this UI.

Appearance selection applies through the existing root `next-themes` provider. Stored custom palettes reuse `applyCustomTheme` and its cleanup owner; this slice does not provide a new custom-palette editor. The native notification list consumes the saved comfortable/compact preference for row spacing while keeping every event label and action available. Job role and use case are editable account metadata. All saves are authenticated self-only and use the canonical profile preference mutation.

No inert language, week-start, rail, cursor or onboarding checkbox controls are exposed. Actual onboarding steps, translated native screens, calendar week alignment, rail/cursor consumers, last-workspace navigation, custom color editing, avatar/mobile/company/goals/marketing preferences and inherited route retirement remain closure work. Stored onboarding flags are preserved, not marked completed by preference edits. This is not full profile or bootstrap parity.
