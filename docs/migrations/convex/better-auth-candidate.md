# Better Auth account boundary

The candidate uses `@convex-dev/better-auth@0.12.5`, Better Auth and its API-key plugin `1.6.33`, and Convex `1.46.0`. The app registers the local `betterAuth` component and its generated schema/adapter. `SUMMON_AUTH_ENGINE=better-auth` selects the native component issuer and its default `/api/auth` routes. The existing Convex Auth tables and alternate issuer remain a rollback and credential-migration boundary. Deployment and CLI environments must select the same engine. Remove the selector and old auth tables only after cutover acceptance.

## Owner and invariant

Application `users` IDs own memberships and authored content. `betterAuthLinks` connects a verified native identity to that stable ID. Account linking rejects ambiguous, unverified, already linked or deactivated application users. A verified email change preserves the application ID, rejects collisions, revokes native sessions and schedules notification to the previous address. Product access checks the authoritative backing session, JWT subject/session ID, verified identity, application link and account restriction; an unexpired JWT alone does not grant access.

Sensitive account changes use native Better Auth credential methods inside the Convex mutation that owns their application effects. Native HTTP deletion, unlink and password-change endpoints are disabled because separate component calls cannot enforce the application transaction. The unused native HTTP profile writer is also disabled; generated application profile/preferences APIs own metadata and revision checks. Deactivation rejects instance administrators and owners without another administrator, disables memberships and retains authored work. Explicitly deactivated accounts cannot sign in again; this matches the current Django security boundary. Account unlinking requires another configured sign-in method and revokes all sessions after success.

## Candidate UI

One native React provider surrounds the application. Sign-in, sign-up, recovery, onboarding, workspace entry, the selected native Stickies route and preserved account Settings use it. Profile, appearance, language, notifications, avatar and cover operations use generated Convex APIs. Settings retains the deployed modal and direct-link presentation. Preserved workspace General and PAT management also use this session. General reads/writes generated settings metadata, publishes private logos through the existing asset owner and awaits note flush before revisioned soft deletion. Other product routes and inherited Power K remain legacy retirement gates.

The provider carries a type-only package patch for the installed Better Auth client plugin tuple. Browser HTTP/file/editor transports obtain their bearer through the native Convex client plugin. The pinned API-key patch awaits native expiry cleanup and preserves unexpected storage failures for Convex retry; it does not add another token store. Component PAT rows/indexes and generated references remain the schema owner.
