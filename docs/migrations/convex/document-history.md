# Document version history and body restore

The existing native `documentRevisions` table owns immutable Yjs binary snapshots. The inherited page-version list/detail endpoints establish history browsing; restoration must preserve the native live CRDT rather than replay old bytes into it.

`documents/history` exposes bounded metadata pages, an authorized source query and an internal commit. Node actions decode historical binary through the canonical editor owner. Preview ignores stored derived HTML; restore replaces the current binary's body with decoded historical content through `replaceDocumentEditorHTML`, keeping the current document title. Derived HTML and JSON are regenerated from the resulting binary. The action captures both current content revision and metadata timestamp; the commit checks current ACL and metadata CAS, then calls shared `saveDocumentSnapshot` for unchanged revision, lock/archive, size and immutable-history checks. The public live-server `saveSnapshot` contract remains unchanged.

A restore creates a new version. Original versions remain unchanged and the prior current version can be restored again to undo the operation. Connected editors merge deletion-bearing updates through the existing snapshot subscription; unsaved concurrent edits retain ordinary Yjs merge semantics and are not represented as an exclusive edit lock. Persisted concurrent content or title/metadata changes reject the captured restore rather than being overwritten.

Three behavior journeys use the actual editor/Yjs converters: historical binary wins over deliberately mismatched derived HTML; restored updates merge in both orders with the existing current binary and remove superseded content; current title and immutable old records remain; restoring the later version reverses the operation. ## Live restore integration correction

Chrome exposed a real integration failure after successful restore: applying a durable snapshot with the string origin `convex-snapshot` made Hocuspocus treat that string as a client connection, schedule another store with empty context, and evict the room with `Convex document authentication required`. A logged local reproduction confirmed it. Durable snapshot merges now use Yjs's default non-client origin, which Hocuspocus broadcasts without scheduling a redundant save. Genuine client edits retain authenticated persistence and all failure quarantine behavior.

The real-Hocuspocus regression fails before the change and passes after it; it also verifies a pending client save merges a later durable snapshot without losing either update or scheduling a contextless save.
