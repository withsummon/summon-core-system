# Preserved production bootstrap and navigation owners

The baseline is the currently deployed `core.withsummon.com` UI, including its dashboard/table composition, menus, keyboard commands and responsive behavior. `/core` remains a migration QA surface. This checkpoint does not mount Convex under the production routes or manufacture legacy DTOs.

## Exact current flow

1. `app/legacy-layout.tsx` mounts `AppProvider`; it creates `StoreProvider`, `StoreWrapper`, `InstanceWrapper`, translation/toast and SWR. `InstanceWrapper` calls `InstanceStore.fetchInstanceInfo`; the existing failure path constructs legacy configuration defaults. Native instance authority/configuration is not a substitute for those public flags. Public workspace-creation availability now exists independently.
2. `AuthenticationWrapper` calls `UserStore.fetchCurrentUser`. That calls Django current-user and concurrently fetches `ProfileStore`, `UserSettingsStore` and `WorkspaceRootStore`. Its redirects read onboarding flags, last/fallback workspace slugs, current memberships and `is_password_autoset`. `StoreWrapper` consumes profile theme/custom palette and local sidebar state. Existing cookie authentication and Convex JWT/session owners must not both write this bootstrap.
3. `WorkspaceMenuRoot` reads current email, creation policy and workspace directory. `SidebarDropdownItem` consumes id/name/slug/logo URL/role/exact member total; it exposes settings and invitation actions by role. Native workspace rows already own identity/slug/name/membershipRole and authenticated logo descriptors, but those descriptors must be rendered by the shared authenticated image owner instead of a fabricated public URL.
4. `ProjectsAppPowerKProvider` reads user, route and issue identity, then mounts workspace/project/work-item creation and edit modals. Its commands consume project/issue/state/label/cycle/module/view stores and permission helpers. Replacing only the workspace menu does not migrate those mutating modal consumers or their route bootstrap.

## Concrete prerequisite delivered

`useWorkspaceNavigation` now has two actual production consumers: WorkspaceMenu and the PowerK open-workspace command. It calls the field-only `ProfileStore.selectWorkspace` write, then navigates to the existing workspace URL. The store patches only `last_workspace_id` after the server accepts the request; it does not spread a stale full profile response over unrelated preferences. Failure propagates to one toast and returns an explicit unsuccessful selection. The ordinary menu click prevents premature Link navigation; modifier/non-primary clicks keep the native link path. PowerK closes only after success. Existing menu DOM, classes, icons and URLs are retained.

This removes the previous discrepancy: the dropdown fired a profile write without awaiting navigation, whereas PowerK did not persist workspace selection. It is the concrete owner to replace once the full native bootstrap can mount. No idle native callback or alternate authentication context was added.

## Native contracts and remaining integration boundary

- Existing native session status, identity profile/preferences, onboarding, account/provider inventory and workspace directory cover their actual semantic fields. Production consumers must switch to generated fields at the owner boundary; do not populate invented `IUser`/`IWorkspace` defaults. Password-setup routing must derive from canonical password/account availability, not guess `is_password_autoset`.
- `identity.preferences.selectWorkspace` (commercial owner,dbfc21483f) provides the native field-only equivalent with current membership validation and latest-profile preservation. It is not called by this production prerequisite. Public workspace-creation availability exists. Public authentication availability must continue to use actual configured provider/mail owners, not privileged instance configuration.
- Exact menu member totals need a real owner. Commercial is preparing bounded current-membership contributions; consumers must exhaust pages and sum current contributions before presenting a total, never show loading as zero. Native human-only account scope and inherited bot exclusion remain explicit constraints.
- Post-login last/fallback destination needs canonical membership/slug resolution. `UserSettingsSerializer.get_workspace` selects the oldest created accessible workspace when the last selection is unavailable; alphabetical `orderWorkspacesList` is only the menu ordering rule. Preserve `next_path` behavior only after validating it as a local route; no raw URL or foreign workspace should confer access. Invitations/settings/create-workspace destinations must be migrated together with the menu actions.
- Coherent cutover is the authenticated workspace shell: replace current-user/profile/settings/workspace bootstrap, permission projections and their mutations in one ownership boundary; then mount existing presentation and its supported child routes. Keep the unconverted shell on Django until each exposed command/modal has a canonical backend path. A subscriptions-to-MobX bridge must have one scoped lifetime and remove the replaced SWR fetch/optimistic rollback path, rather than allowing two server-state writers.
