# Document duplicate owner

The registered inherited `PageDuplicateEndpoint` copies scalar page metadata, parent and all project bindings, changes name to “(Copy)” and ownership to the actor, resets binary and asynchronously copies referenced image assets. It does not copy many-to-many page labels, child pages, history or favorites. Native duplication preserves this boundary, including lock/archive flags and extension metadata. It requires current source readability, workspace write permission and writer permission in every preserved project; an unavailable parent rejects rather than silently moving the copy.

`documents.copyActions.run` accepts a captured document content revision, metadata timestamp and request ID. Canonical editor helpers inspect `imageComponent` nodes in the document schema, remap their source IDs and seed a fresh CRDT with the copied title. No regex parser or competing HTML converter is introduced. An unfinished, missing, inaccessible or foreign-document image rejects the operation. Up to 100 referenced assets and 32 MiB are supported explicitly; no truncation is presented as a complete copy.

The private `documentCopies` job and pending `assets.documentCopyId` rows reserve stable destination IDs before conversion. Public asset access, finalization, download and restore reject staging rows through the existing asset scope owner. Each independent storage copy is verified against source size/hash and records a durable cursor. A retried request resumes that cursor or returns its already-published document; changing request inputs rejects. Bytes stored just before an interrupted progress mutation remain covered by the existing global orphan sweep. A durable scheduled expiry removes claimed staging bytes after 15 minutes; published files have their staging marker removed and are not deleted by that job cleanup.

Publication rechecks current source content/metadata CAS, workspace/project/parent access and captured parent timestamp, all referenced ready source bytes and destination receipts. The new document, first immutable snapshot, parent edge and ready asset bindings appear in one mutation. The shared snapshot owner validates derived formats and sizes; lock/archive flags are applied after seeding within that transaction. Historical labels and independent child/history/favorite records are not invented. Document asset bytes have immutable metadata/storage identity rather than a document-asset revision field; ready status, storage ID, size and hash are rechecked at publication.

Eight behavior journeys cover metadata/parent fidelity without copied labels, independent file deletion ownership, title/schema conversion, idempotent retry, unpublished-file denial, durable resume, expiry and published-copy safety, source/parent changes, missing/revoked/foreign asset access, guest denial and explicit budgets.
