## Smallest retirement candidates and stopping rules

1. **Profile/contact/basic settings subjourneys:** project profile read/save, client-contact CRUD and editable workspace settings have native business owners. These are candidates for migrating their specific UI callers first, after field/role/error acceptance. Settings logo projection and full-record versus PATCH differences prevent calling their REST endpoints drop-in replacements.
2. **Resource CRUD with explicit supported associations:** native CRUD has browser evidence. Credential association and sidebar mean the complete legacy resource screen cannot yet disappear without reducing features. Retire only a caller proven not to consume those contracts, or close that gap first.
3. **Basic task/comment/subscription journeys:** native first slice and comments now have local acceptance reported by the parent. Legacy issue routes bundle additional features above; replacing an entire detail route would lose them. Route replacement requires an explicit product scope decision or further implementation.
4. **Keep workflow families with known missing outputs:** meeting summary/transcription, generated artifact render/download, assistant attachment/action families, inherited cycles/modules/intake/views and complete reports have concrete missing operations. Do not retire them based on CRUD or transport tests.
5. **Delete only after consumer closure:** migrate imports/routes, verify served candidate network traffic and roles, preserve external API contracts explicitly, then remove unreachable service methods/URLs/workers with rollback. No complete legacy route family or Django/Postgres shutdown is approved by this source inventory alone.

## Addendum after inventory: `10da39c21e`

The tables above describe `ba52bcfca9`. Subsequent slices close these bounded gaps:

- Resources can associate an existing authorized credential; inaccessible credential metadata is redacted while the resource remains independently editable. Explicit detachment is supported.
- Assistant conversations accept private TXT/MD/CSV attachments with validated upload/extraction, bounded context, recovery and idempotent message acceptance. PDF/Office/image extraction and real provider execution remain open.
- Meetings accept supplied transcript text, preserve it in the canonical private document, and execute a structured summary adapter with provenance, authorization and revision checks. Live provider output and recording transcription remain unverified/unimplemented respectively; no automatic task creation is introduced.
- Existing canonical editor content is replaced with Yjs deletion history preserved, preventing old/new content union in connected editors; generated document titles agree with server metadata.

These changes do not remove the legacy route registrations or establish external REST compatibility. See the current [acceptance record](README.md) for verification boundaries.
