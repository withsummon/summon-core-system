Problem

Summon Core saat ini dibuat sebagai frontend Next.js dan API NestJS terpisah. Plane sudah menyediakan fondasi project management yang lebih lengkap: workspace, project, work item, member, state, cycle, module, view, page, asset, notification, activity, analytics, authentication, permission, dan settings. Menyalin seluruh model dan layar lama ke fork akan menghasilkan dua sumber data untuk konsep yang sama.

Selain itu, nama target withsummon/summon-core-system sudah dipakai repository Next.js. GitHub tidak dapat membuat fork Plane dengan nama dan owner yang sama sebelum repository lama dipindahkan namanya.

Keputusan kickoff: pekerjaan ini bukan menempelkan dua aplikasi. Plane menjadi platform utama; kode lama hanya menjadi referensi perilaku dan acceptance.

Approach

1. Extension boundary

Tambahkan satu Django app plane.summon di apps/api untuk model, migrations, serializers, services, permissions, dan API domain Summon. Semua foreign key langsung menunjuk model Plane Workspace, User, Project, Issue, Page, atau FileAsset. Setiap query dan mutasi wajib memvalidasi workspace dan project membership, bukan hanya keberadaan UUID.

Frontend ditempatkan sebagai feature folders di apps/web, memakai service/store/component bawaan Plane. Route Summon masuk melalui apps/web/app/routes/extended.ts dan pola extension yang sudah ada. Shared contracts masuk ke package Plane yang relevan hanya bila dipakai lintas feature.

2. Minimal persisted schema

Commercial
Client, ClientContact, Opportunity, SummonProjectProfile.
Collaboration
Meeting, MeetingParticipant, MeetingWorkItem, SummonPageContext, ResourceLink.
Automation
AutomationTemplate, AutomationJob, GeneratedArtifact yang menunjuk Page/FileAsset.
Security
Credential, CredentialGrant, CredentialAccessLog.
  • SummonProjectProfile tidak menyimpan nama project, member, progress, atau task count.
  • MeetingWorkItem tidak menyimpan title, status, assignee, atau due date; semua dibaca dari Issue.
  • GeneratedArtifact tidak menyimpan file content; hanya relasi hasil ke Page/FileAsset dan metadata job.
  • ResourceLink hanya untuk URL eksternal dan metadata display; file upload tidak masuk ke tabel ini.
  • CredentialAccessLog tetap dipersist karena reveal, rotate, grant, revoke, dan delete tidak dapat direkonstruksi aman dari state akhir credential.

3. Feature delivery slices

  1. Fork baseline and branding: repo transition, clean Plane boot, Summon name/logo/copy, preserved AGPL notices, and upstream remote.
  2. Canonical work management: configure Plane project/work item/page/notification/settings paths and add SummonProjectProfile plus Summon home summary.
  3. Commercial: Clients, contacts, Opportunities, pipeline transitions, client detail, and links to Plane projects.
  4. Knowledge and resources: workspace knowledge index over Pages, document index over FileAssets, and persisted external ResourceLink entries.
  5. Meetings: meeting schedule, participants, notes, recording/transcript assets, summary, and action items backed by Plane Issues.
  6. Automation and assistant: deterministic templates/jobs, generated Page/FileAsset outputs, assistant queries over authorized canonical data, and command palette extensions.
  7. Credential Vault: encryption, masking, re-authenticated reveal, grants, rotation, revocation/deletion, and audit history.
  8. Reports and operational finish: portfolio/commercial/project/task/automation aggregates, exports, custom settings, notifications, responsive parity, and legacy runtime retirement.

Setiap slice harus selesai dengan migration, backend test, frontend check, dan browser read-back sebelum slice berikutnya dianggap complete.

Acceptance Criteria

Repository and architecture

  • GitHub menunjukkan withsummon/summon-core-system sebagai fork dari makeplane/plane.
  • origin dan upstream mengarah ke repository yang benar; SHA baseline stable tercatat.
  • Build, Compose, runtime, dan deployment tidak mengacu ke repository Next.js atau NestJS lama.
  • Tidak ada Next.js app, NestJS app, Drizzle schema, atau OpenAPI contract lama di fork Plane.
  • Copyright dan AGPL-3.0 Plane tetap utuh; source availability untuk deployment jaringan ditangani sebelum produksi.

No redundancy gate

  • Tidak ada custom model bernama atau berfungsi sebagai Project, Task/Issue, User, Session, Workspace, Page/Knowledge content, FileAsset/Document binary, Notification, atau Settings preference umum.
  • Setiap custom row memiliki workspace scope; project/user/issue/page/asset reference memakai primary key Plane.
  • Progress, task counts, report totals, and recent activity dihitung dari source canonical, bukan disimpan sebagai copy.
  • Meeting action item completion hanya dimiliki oleh Plane Issue.
  • Generated document content hanya dimiliki Page/FileAsset Plane.
  • Custom domain events memakai notification Plane dan permission Plane.

Feature parity

  • Sembilan halaman PDF terwakili: login/home, project workspace, knowledge, reports, client detail, credential vault, command palette, settings, opportunities, resources, automation, assistant, task center, meeting, dan notifications.
  • UI memakai visual language Plane; PDF menjadi referensi informasi, hierarchy, dan feature presence, bukan permintaan membuat shell kedua atau pixel-copy.
  • Semua kontrol yang terlihat actionable melakukan navigation, persisted mutation, download, atau membuka form/modal yang benar. Placeholder toast tidak diterima.
  • Loading, empty, validation, forbidden, not-found, conflict, and recoverable server-error states tersedia pada custom flows.
  • Desktop dan mobile tidak overflow dan seluruh custom route dapat dicapai melalui navigasi Plane serta command palette.

Security and data integrity

  • Workspace/project access diverifikasi server-side untuk list, detail, mutation, asset download, reports, assistant, automation, dan credential operations.
  • Credential secret dienkripsi memakai dependency cryptography yang sudah ada dengan dedicated runtime key dan key version. Secret tidak muncul di list/detail response, logs, migrations, seed, screenshots, atau Git history.
  • Reveal membutuhkan session aktif, password re-verification, dan grant yang sesuai; response tidak di-cache dan UI menghapus secret saat drawer ditutup, selection berubah, tab hidden, atau timeout.
  • Cross-workspace foreign keys ditolak walaupun UUID valid.
  • Database constraints melindungi uniqueness, probability range, stage/status vocabulary, dan exactly-one/allowed relationship invariants.

Verification

  1. Baseline: jalankan setup self-host Plane dan buktikan frontend, API, PostgreSQL, Redis/Celery dependencies bawaan, dan health endpoints berjalan sebelum custom code.
  2. Static checks: pnpm check dan pnpm build untuk monorepo Plane.
  3. Backend: migration dari database kosong dan focused Django/pytest tests untuk setiap custom service, permission, constraint, and transition.
  4. Plane regression: docker compose -f docker-compose-test.yml up --build --abort-on-container-exit --exit-code-from api-tests untuk shared model/permission changes; subset test boleh dipakai selama slice, full gate wajib sebelum release.
  5. Duplicate audit: periksa Django app registry dan PostgreSQL tables untuk memastikan custom table hanya sesuai allowlist schema pada plan ini.
  6. Browser acceptance: Playwright menjalankan flow Sign in, Project/work item, Client/opportunity, Page/FileAsset/ResourceLink, Meeting/Issue action, Automation output, Credential reveal/audit, Notification, Report, dan Assistant.
  7. Visual: screenshot desktop dan mobile untuk setiap kelompok route PDF, cek hierarchy, accessibility basics, responsive layout, dan console errors.
  8. Repository: git diff --check, review diff terhadap upstream stable, pastikan generated/temp files dan secrets tidak ter-commit.
  9. Deployment proof: verifikasi commit SHA yang live, login nyata, satu persisted write/read-back, asset download, dan credential masking pada deployment target sebelum legacy runtime dinonaktifkan.

  • Plane UI tetap menjadi shell utama.
  • Plane Django API dan PostgreSQL menjadi backend tunggal.
  • Repository Next.js dan NestJS lama tidak menjadi runtime dependency.
